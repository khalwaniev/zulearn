## Deduplication taxonomy and operational ledger

| Class | Required evidence | Decision |
|---|---|---|
| IDENTICAL | Same underlying task/constraints/oracle, or a verified common item identifier | One attempt; retain both source memberships, count once |
| NEAR-IDENTICAL | Inspected prompts differ only superficially or by syntax/data names | Skip after an independent changed-task gate |
| SAME IDEA, DIFFERENT IMPLEMENTATION | Same mathematical estimator, new backend or interface | Keep only when backend semantics/performance is the target |
| MEANINGFUL VARIATION | Changed constraints, numerical conditioning, sampling, assumptions or failure mode | Keep the specific variation and articulate the added skill |
| ADDITIONAL THEORY | A proof/identifiability/complexity obligation absent from the guided task | Keep the theory task selectively |
| INDEPENDENT TRANSFER | New representation/problem family with no copied solution path | Reserve for assessment; mark exposed after use |
| RESEARCH GAP | Competence not established by either platform's inspected tasks | Add a domain/experimental/theoretical resource with a gate |
| UNKNOWN | Titles/tags only, premium contents unavailable or metadata insufficient | Do not quantify overlap; inspect on demand or choose a known alternative |

Ledger schema: `local_id; exact platform URL or source title+ordinal; snapshot date; task objective; math idea; required proof; constraints; backend; access; estimated/actual effort; prerequisite IDs; duplicate_of; relationship class; evidence; independent outcome`. Start with `UNKNOWN` for item equivalence. Never promote concept-level overlap into an exact duplicated-exercise count. D001 and a TensorTonic dot-product title show shared concepts, not an audited identical prompt pair.

## Selected Deep-ML projects and stopping points

Use the companion catalogue inventory for exact observed project titles/step counts. A project number printed in a card is not assumed to be a stable URL ID. Default choices: one autodiff build; one regression/inference pipeline; one small neural network; one LSTM; one GPT or full Transformer according to the active question; one basic RL/planning build; one GNN; one causal interpretability experiment. These are spread across stages, not simultaneous work. Choose a small empirical lab after the relevant concept, then add independent validation that the harness omits.

Skip overlapping alternative Tiny GPT/GPT-1/full-Transformer variants until an objective demands their differences. Defer compiler/MoE/distributed/GPU stacks without a bottleneck. Exclude market-making/betting and unrelated commercial capstones; preserve reusable mathematical techniques in nonexcluded contexts. Named contemporary architecture projects are catalogue observations, not verified claims that a paper exists or that its scientific conclusions are correct.
