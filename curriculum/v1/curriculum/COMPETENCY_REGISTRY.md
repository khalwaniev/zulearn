# Competency registry — entry and depth separated

> Version 1, 2026-11-27: bounded corrective revision after human-reported conditional independent approval. Curriculum architecture fixed for learning; local queues and learner evidence remain adaptive. Live GitHub integration awaits approval of this revised package.

Only **F01.basic_ops** (basic addition, subtraction, multiplication and division) is provisionally fluent by self-report. Begin **F01.fraction_meaning and C01 Python** now; elementary algebra follows the supplied queue. Decimals, percentages, ratios, negatives, exponents and other arithmetic topics are not assumed. Other skills are not assumed mastered. This registry is a navigation map, not an entrance examination or a demand to complete entire parent courses before learning.

**Entry prerequisites** name the small operations needed for a first lesson. Use the actual local subskill, such as substitution or a finite weighted sum; the parent module need not be fully confirmed. A worked explanation can establish that operation during the lesson. **Depth dependencies** apply to a later proof, implementation, research claim or method branch, and do not delay entry. “For X” and “or” are conditional; do not silently turn them into a cumulative AND gate.

`W` means independently solve/explain/derive/implement the relevant subskill with assumptions and failure cases; `R` means research-critical scrutiny when that branch is active. Both require later independent evidence, never AI-assisted output alone. `UNASSESSED` is an evidence state, not a prohibition on learning.

The 109-row scope preserves all 102 baseline competency IDs and adds only seven explicit coverage nodes: Monte Carlo, VI, fixed points, programming abstractions, SSL, post-training and verifier-guided reasoning. New detail is largely taught inside existing nodes. No additional whole-degree or course-completion requirement is created.

Resource names `D001`–`D112` remain local aliases of observed Deep-Path ordinals, not fabricated exercise IDs. Worksheet namespaces and exact definitions are in [WORKSHEET_INDEX](WORKSHEET_INDEX.md); diagnostic-bank questions are `DX-A1` etc., kept separate from worksheet IDs. Local first-week tasks are `START-01`–`START-07` in the [workflow](../operations/WEEKLY_DAILY_WORKFLOW.md).

## Local evidence and acceleration

Use rows only as far as the next task needs them. Teach first, ask one or two short questions about the just-used operation, and remediate the precise error immediately. If the learner already explains and solves two varied unaided examples, skip repetitive instruction and schedule a later fresh sample. This is a local administrative heuristic, not a validated universal mastery threshold. No all-correct escalation until failure is required.

Store subskills such as `F02.notation`, `F02.equality`, `M07.finite_conditioning`, `M07.continuous_transform` separately in [learner state](../templates/LEARNER_STATE.md). Passing finite probability does not imply mastering multivariate densities; failing confidence-interval interpretation does not erase an independently demonstrated likelihood calculation. Mathematics, programming, DSA and introductory data/model reasoning have concurrent starting lanes in the master/workflow.
